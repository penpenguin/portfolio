[i-have-adhd](https://github.com/ayghri/i-have-adhd)は、コーディングエージェントの返答を、すぐ行動に移せる形へ整えるスキルです。新しいモデルを提供するものではなく、回答の順序や手順の区切り方をMarkdownで指定します。READMEは、利用にADHDの診断は不要と明記しています。

狙いは単なる短文化ではありません。長い説明からコマンドを探し、前の返答まで戻って進捗を確認する。その手間を減らすために、答えと現在地を見える場所へ置く設計です。

## 短くするより、行動を先に置く

中心となる`SKILL.md`には、次の行動から始める、複数の手順には番号を振る、脱線を抑える、といったルールが並びます。コマンドやファイルパスが答えなら先頭に出し、作業が残る場合は最後に具体的な一手を示す。進捗も各ターンで示し、読み手の記憶だけに頼らない構成です。

ここで見落としたくないのは、省略の限界も書かれていることです。リストは一群あたり最大5項目を目安にまとめますが、網羅性が必要な情報を捨ててよいわけではありません。調査や分析まで5件に制限するルールでもない。

「詳しく説明して」と頼まれたら必要な長さで説明し、破壊的な操作では短さより確認を優先する。選択肢を求められたときも、一つに決めつけず比較を残します。「短く答える」という指示だけより、用途との衝突を扱いやすい作りです。

## Claude Codeでは必要なときに有効化する

公式の導入手順では、Claude Codeに次のコマンドで追加します。以下はドキュメントに基づく手順で、この記事では実機での動作確認はしていません。

```bash
claude plugin marketplace add ayghri/i-have-adhd
claude plugin install i-have-adhd@i-have-adhd
```

追加後に`/i-have-adhd`を呼び出すと、そのセッションでルールを使うよう指示されます。`stop adhd mode`または`normal mode`で解除する設計です。通常はインストールだけで出力が切り替わるわけではありません。

毎回有効にしたい場合は、標準の設定ディレクトリに`~/.claude/.i-have-adhd-always`というフラグファイルを置きます。公開されている`SessionStart`フックは、その存在を確認してスキル本文を読み込みます。設定ディレクトリを変更している場合は、`CLAUDE_CONFIG_DIR`側に置く必要があります。

まずは手動で呼び出し、普段の説明量と合うかを見るほうが、常時有効化から始めるより比べやすそうです。

## 原因まで言い切らせない

公開評価も、導入前に読んでおきたい資料です。`evals/RESULTS.md`では、スキルなしとありの返答を比較し、行動の明確さや簡潔さのスコア改善を報告しています。ただし、同じモデルが生成と採点を担当した評価であり、公開されたリリース判定は不合格です。

具体的には、根拠がないのにエラー原因を「認証ヘッダーの欠落」と断定した返答が問題になっています。資料は、「原因と修正方法を示す」というルールが、証拠の足りない場面でも原因を言わせてしまう可能性を挙げています。ただし、その因果関係までは確認されていません。

この注意点は、出力を整えるスキル全般にも通じます。読みやすさと正しさは別に確認したい。試すなら、答えが明確な質問だけでなく、失敗原因がまだ分からないログも渡してみる。次の操作をすぐ見つけられるかに加え、「まだ分からない」を残せるかが、使い続けるかどうかの判断材料になります。
