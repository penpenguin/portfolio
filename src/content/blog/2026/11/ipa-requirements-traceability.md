社内FAQで「出張の申請は何日前までか」と尋ねたら、有効な規程が二つ見つかり、それぞれに違う期限が書かれていた。こんなとき、片方の期限を即答するより、答えを保留して担当者に確かめてほしい。「正確に回答すること」という要件だけでは、その違いをテストできません。

IPAの『AI時代の要求管理ハンドブック』は、AIを使って要求を整理する側と、AIシステムに何を求めるかを決める側の両方を扱っています。[1] FAQの設計で参考になるのは、判断が難しい場合の振る舞いを扱う5.3節と、要件を変更したあとに何を検証し直すかを扱う6.6節です。[2]

## 回答を保留する条件

5.3節の問い合わせ分類の例では、分類の精度と、人間の確認に回す条件を分けています。たとえば、確信度が一定値を下回れば自動分類を見送ります。[2] モデル全体の成績と、目の前の一件を任せてよいかは別の問いです。

冒頭のFAQに当てはめてみます。以下は本書の事例とは別に作った練習問題です。目的は「根拠のない期限を社員に案内しないこと」。当初の要件は「有効な規程があれば回答し、なければ担当者に回す」とします。ここに「有効な規程同士で期限が食い違う場合も担当者に回す」という条件を加えます。

## 同じ入力で変更前後を比べる

規程の有効性と期限の食い違いは判定済みと仮定します。次のPythonコードは検索も文章生成もせず、その判定を受けたあとの振り分けだけを比べます。

```python
cases = [(True, False), (False, False), (True, True)]
for current, conflict in cases:
    old = '回答' if current else '担当者へ'
    new = '回答' if current and not conflict else '担当者へ'
    print(current, conflict, old, new)
```

| 入力                           | 変更前   | 変更後   |
| ------------------------------ | -------- | -------- |
| 有効な規程があり、期限は一致   | 回答     | 回答     |
| 有効な規程なし                 | 担当者へ | 担当者へ |
| 有効な規程があり、期限は不一致 | 回答     | 担当者へ |

実行すると、振り分けが変わるのは最後の一件だけです。最初の二件だけをテストしていたら、旧実装のままでも合格します。そこで、期限の異なる二つの規程をテストに残し、期待する結果を「どちらかの期限を答える」ではなく「回答を保留して担当者に回す」と記録します。このテストだけでは、実際の文書から期限の矛盾を見つけられるかまでは分かりません。

## 変更した要件から運用までたどる

6.6節では、要件を設計・実装・テスト・運用と関連付けておき、変更時に再確認する対象を絞ります。AIが挙げるのは影響を受けそうな箇所の候補で、変更範囲や受け入れの可否を自動で確定するわけではありません。[2]

FAQなら、変更した要件に、振り分け処理、期限不一致のテスト、担当者の受付手順を結び付けます。コードが「担当者へ」を返しても、受付画面に質問しか届かなければ、担当者は食い違った規程を探し直すことになります。そこで受入確認では、二つの規程を担当者が画面から開けるところまで試します。テストが一つ増えたことよりも、**誰が何を確認すれば回答を再開できるか**が決まったことに、この変更の意味があります。
