SpriteCookの作例では、青いレースカーがコーナーを曲がっても、方向ごとの車の絵を切り替えていません。用意したのは車体を水平に切った15枚の断面です。タイヤの底から屋根までを順に重ね、どの断面にも同じ角度を与えます。車がどちらを向いても、高いところにある断面をずらす方向は画面の真上です。[1]

## シートの左端から屋根まで

シートの各コマは時間順のアニメーションではなく、高さの順に並んでいます。車の例では1コマが横24、縦43ピクセル。左端はタイヤが地面に触れる高さの断面なので、そこに車体全体の形はありません。次の断面を1ピクセル上に描き、さらにその上に次の断面を描くと、下の絵は上の絵からはみ出した分だけ見えます。元記事には同じ車を3ピクセル間隔に広げた図があり、どの層が窓や屋根を形作るのかを見比べられます。[1]

## 1点を90度回してみる

積み上げた車を最後に丸ごと回すとどうなるでしょうか。回転と高さの関係だけを取り出した自作の例で確かめます。画面の右をxの正方向、下をyの正方向とし、中心から右に2ピクセル、高さ3の点を選びます。層の間隔は1ピクセルで、縦方向の縮小はしません。

```python
def turn(x, y):
    return -y, x  # 画面上で時計回りに90度

x, y, z = 2, 0, 3
rx, ry = turn(x, y)
print((rx, ry - z))  # 回してから上へ
print(turn(x, y - z))  # 上へずらしてから回す
```

Pythonで実行すると、順に `(0, -1)` と `(3, 2)` が出ます。地面と同じ高さなら、回転後の点は `(0, 2)` にあります。前者はその点の真上に3ピクセル、後者は右に3ピクセルです。後者では屋根の高さが横ずれに変わってしまいます。この計算で確かめたのは座標の違いで、車を描画した結果や処理速度ではありません。

## Godotで断面を描く順序

SpriteCookのGodot実装は、`Node2D` の `_draw()` で断面ごとに `draw_set_transform_matrix(lift * spin)` を呼びます。点に先に作用するのは右側の `spin` です。各断面を中心のまわりで回し、`lift` で縦に縮めてから、その層の高さだけ上へ移します。描画するたびにシートから読み取る範囲を1コマ右へ送るのが `draw_texture_rect_region()` です。GodotのAPIでは、変換行列は後続の描画に作用し、読み取り元の矩形と描画先の矩形は別々に指定します。[1][2]

車と街路樹が重なる場面では、車の屋根と木の枝を層ごとに並べ替えると、枝が車体の途中に挟まることがあります。そこで、どちらを手前に描くかは地面に接する位置で決め、車はタイヤから屋根までをひとまとまりとして描きます。逆に、視点に対する向きが変わらない木なら、最初に断面を重ねた画像を1枚作って使い回せます。回転する車と同じ描き方を、背景の木にまで適用する必要はありません。[1]
