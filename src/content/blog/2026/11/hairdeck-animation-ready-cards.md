[HairDeck](https://hyzcluster.github.io/HairDeck/)はキャラクター画像1枚からアニメ調の3Dヘアを生成する研究です。出力には毛束を表すヘアカードと、髪を揺らすスプリングボーンが含まれます。髪形を一体のメッシュにまとめず、毛束ごとの構造を残す点が特徴です。

以下は論文と公開コードに基づく解説です。推論やVRMへの書き出しは実行していないため、生成品質や手元の環境での速度を評価した記事ではありません。

## 毛束を単位にした生成

HairDeckが扱うカードは、透明なテクスチャで細い毛を描く写実的な髪の板とは異なります。幅や厚みを持つ帯状の形状そのものが、アニメ調の毛束になります。

論文ではカードの制御点列をVAEで圧縮し、根元の位置・向き・断面の種類と合わせて1トークンにします。トークンはここでは文章の単語ではなく毛束の形状を表す数値のまとまりです。

髪形全体は順序のないカードの集合として扱い、位置埋め込みを使わない拡散Transformerでまとめて生成します。各トークンにはカードが存在するかを示す値もあり、出力する毛束の数を決めます。制御点を順に長く並べて生成するCHARMとは生成する単位と順序の扱いが異なります。

さらに別のTransformerが、カードのトークンを条件にボーンのチェーンを生成します。チェーンには経路、関節数、剛性が含まれ、幾何学的なスキニングでカードを結び付けます。形状の生成と、その形状を動かすためのボーン生成を分けた構成です。

## 入力から出力までの確認手順

公式READMEでは、環境とモデルを準備したあと、リポジトリのルートで次のコマンドを実行する例が示されています。入力の`character.png`から4候補を生成し、候補0をVRMと頭を動かす動画へ書き出す手順です。

```bash
python scripts/image_to_hair.py character.png --out results/my_character --n 4
python -m hairdeck.vrm.export results/my_character/character 0
```

最初のコマンドの保存先は`results/my_character/character/`です。READMEとCLIの実装によれば、seed 0の出力は次のように分かれます。

- `prep.png`と`model_input.png`: 前処理のマスク・切り抜きと、モデルに渡す画像。
- `cards_seed0.json`と`chains_seed0.json`: 毛束の形状・色と、生成したボーンのチェーン。
- `hair_seed0_nohead.glb`: 頭部の仮モデルを含まない髪のメッシュ。
- `avatar_seed0.vrm`と`turn_seed0.mp4`: VRM書き出し側で作るアバターと動作確認用の動画。

確認の順序もこの分かれ方に合わせると原因を切り分けやすくなります。髪の範囲が入力から欠けているなら、まず前処理の画像を確認します。形が合わないならGLBで前後の形状を見比べ、形は合うのに揺れが合わないならボーンと動画を確認します。静止画で似ていることと、動くアセットとして使えることは別々に判断したいところです。

とくに、CLIが最後に`ok`を表示しただけでボーン生成まで成功したとは判断できません。実装にはチェーン用モデルを利用できない場合に`chains off`を表示して続行する経路があります。揺れが必要ならログと`chains_seed0.json`の有無を確認し、VRMの動作も確かめる必要があります。`--no-chains`を指定した場合もチェーンのファイルは出力されません。

## ローカル実行の準備

公開READMEにはNVIDIA CUDA向けの導入手順があり、Apple silicon向けにはMPSで動かす専用の案内があります。ただし、MacでGLBを生成することと、VRMを書き出すことでは準備が異なります。

macOSの案内では、GLB出力にBlenderは不要です。VRMと頭を動かすプレビューにはBlenderとVRM Add-onが必要で、`HAIRDECK_BLENDER`で実行ファイルを指定します。macOSではダウンローダーがBlenderを自動導入しないため、READMEの共通手順だけで準備が終わるとは限りません。

また、前処理などに使うSAM 3とDINOv3は、Hugging Face上で利用条件への同意が必要です。HairDeck本体のコードとチェックポイントはApache-2.0ですが、外部モデルやデータにはそれぞれのライセンスが適用されます。

## 対象に合う髪形の選び方

論文はVRoid系の髪形を学習対象としており、極端に短い髪や、透明テクスチャを使う写実的なヘアカードは学習データの範囲外としています。頭頂部から多数のチェーンが放射状に伸びるような珍しい構成では、チェーンが少なく生成される問題も報告されています。

色の扱いは資料の時点にも注意が必要です。論文v1にはテクスチャを生成しないとありますが、公開READMEの11月5日の更新では、カードに沿った色を予測するモデルとGLB・VRMへの色の出力が追加されています。UVがあること、色を出力すること、画像テクスチャを生成することは区別して読む必要があります。

アニメ調の毛束を編集し、揺れも付けたい用途なら検討しやすい技術です。最初の評価では、入力画像への見た目の近さに加えて、毛束の分かれ方と必要なチェーンが残るかを確認すると、手作業で直す範囲を判断しやすくなります。
