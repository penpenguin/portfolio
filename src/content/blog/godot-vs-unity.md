## GodotとUnity、ざっくりどう違う？

一言でまとめると、

- Godot = 完全無料・オープンソースで、2D中心のインディーや小規模開発に向きやすいエンジン
- Unity = 商用サブスク型で、コンソール・モバイル・3D・VR/ARなど「業界標準」に近いエンジン

というイメージです。

もう少し整理してみます。

## まずは早見表で比較

| 項目 | Godot | Unity |
| --- | --- | --- |
| ライセンス・料金 | MITライセンス、完全無料、ロイヤリティなし | 個人・小規模向けの Unity Personal は無料だが、一定の売上/資金を超えると Pro/Enterprise の有料サブスクが必要 |
| ソースコード | フルオープンソース（GitHubで公開） | クローズドソース（Unity Technologiesの商用製品） |
| 主なスクリプト言語 | GDScript（Godot独自）＋ C# ＋ C++ / GDExtension | C#（.NETランタイム上） |
| 得意分野の傾向 | 2Dゲーム、インディー、小〜中規模 | モバイル、コンソール、3D、VR/AR、大規模タイトル |
| コンソール対応 | 公式には非対応（パートナー経由のポーティング） | 公式で主要コンソールに対応 |
| エコシステム | コミュニティ主導、公式Asset Library | 巨大なAsset Storeと周辺サービス群 |
| 運営主体 | Godot Foundation（非営利）＋コミュニティ | Unity Technologies（営利企業） |

ここから、ポイントごとにもう少しだけ詳しく見ていきます。

## 1. ライセンスとお金の違い

### Godot：MITライセンスで完全無料

Godotは MITライセンス のオープンソースエンジンです。
エンジン自体の利用料やロイヤリティは一切かかりません。

MITライセンスの要求はシンプルで、ゲーム内やクレジットなどにライセンス文を入れる程度 です。ゲーム本体をオープンソースにする義務もありません。

- 売上がいくらになってもロイヤリティなし
- オフライン・社内利用も基本的に制限なし

という意味で、ビジネス面の条件がかなり安定・シンプル です。

### Unity：無料枠はあるが、一定規模からは有料サブスク

Unityは商用製品で、プランごとの条件が細かく決まっている タイプです。

- Unity Personal
  - 無料
  - 過去12か月の売上＋調達資金が 20万ドル未満 の個人・小規模組織が対象
- Unity Pro / Enterprise
  - 20万ドルを超えるとPro以上が必須
  - 2025年時点で、Proはおよそ 年額2,200ドル/席 → 2026年から約2,310ドル/席に値上げ予定

2023年に「インストール数に応じたRuntime Fee」を発表して大炎上 → 2024年に Runtime Fee自体は撤回され、再びサブスク中心の料金体系に戻る という経緯があります。

インディー規模なら今もUnity Personalで実質無料 ですが、

- 将来売上が大きく伸びたとき
- 受託開発・企業案件など

では、Pro以上の費用が確実に発生する前提で設計した方が安全 です。

## 2. 言語と開発体験の違い

### Godot：GDScript中心、学びやすさ重視

Godotのメイン言語は GDScript。
見た目や文法はかなりPythonに近く、Godot専用に設計されています。

Godot 4.0以降では 任意の静的型付け（型アノテーション） が追加され、パフォーマンスや補完精度も改善されています。

加えて、

- C#（.NET）
- C++ や他言語を拡張として組み込める GDExtension

なども選べます（C#対応エディタは .NET版Godotを別途ダウンロードする必要あり）。

特徴的なポイント

- GDScriptはGodotのAPIと非常に密に統合されていて、チュートリアルやサンプルもGDScriptが中心
- 「ゲーム開発を通してプログラミングを学びたい」人にはとっつきやすい

という意味で、初学者〜インディーにかなり向いた言語設計 になっています。

### Unity：C#一択に近い、業界標準寄り

Unityのスクリプトは基本的に C# 一択 と思っていいです。

- .NETランタイム（Mono / IL2CPPなど）の上で動く
- Visual Studio や Rider など一般的なIDEと連携しやすい
- C#自体がゲーム業界でも企業システムでも広く使われる言語

という事情もあり、「ゲーム以外の仕事にも直結しやすいスキル」 になりやすいのがUnity側の強みです。

## 3. 2D / 3Dと機能の違い

### Godot：2D特化感が強く、小〜中規模の3Dも十分

Godotは 専用の2Dレンダラーを持っている のが特徴で、2Dゲームではかなり使い勝手が良いです。

- 2Dはピクセルベースで扱いやすく、カメラやUIも2D向けノードが充実
- 3DもGodot 4系以降で大幅に強化されており、物理・GI・Navmeshなど一般的な機能はひと通り揃う

ただし、超リッチなAAA級3Dグラフィックスや、大規模オンラインゲーム向けに作られたエンジン ではないので、

- フォトリアル3D
- 大規模マルチプレイ
- コンシューマ機向けでガッツリ3D

といった領域では、UnityやUnrealの方が事例は多いです。

### Unity：3D中心で、2Dも幅広くカバー

Unityはもともと3Dエンジンで、2Dは3D環境の上に2D機能を乗せている形です。

- URP/HDRPなどのレンダーパイプライン
- 豊富なポストエフェクト、シェーダーツール
- アニメーション、タイムライン、シネマティクス

といった3D関連機能に加え、2D物理・タイルマップなども充実しており、
2D〜3Dまで「幅広いジャンルの商用ゲームで実績がある」 ことが最大の売りです。

例として、

- 『原神（Genshin Impact）』：Unity製の大規模オープンワールドARPG
- 『Hollow Knight』：Unity製の2Dアクション・メトロイドヴァニア

など、世界的ヒット作が多数あります。

## 4. 対応プラットフォームとコンソール

### Godot：PC / モバイル / Web は強いが、コンソールはパートナー経由

Godotエディタとエクスポート先は、

- Windows / macOS / Linux
- Android / iOS
- Web（HTML5）

など主要なプラットフォームを公式にサポートしています。

一方で、PlayStation / Xbox / Nintendo Switch などのコンソールは、オープンソースの性質上「公式サポートなし」。
コンソール版を出すには、ライセンス契約を結んだポーティング会社やパブリッシャーを通す必要があります。

### Unity：コンソールを含めたマルチプラットフォームが前提

Unityは、

- PC（Windows / macOS / Linux）
- モバイル（iOS / Android）
- 主要コンソール
- VR / AR デバイス

など、20以上のプラットフォームにC#コードをビルドしてくれる前提で設計されたエンジン です。

コンソール向けの開発環境は、各プラットフォーマーとの契約は必要ですが、
エンジンとしてのサポートはUnity側で公式に提供されている ため、

- 「コンソール前提の企画」
- 「パブリッシャーやクライアントからUnity指定」

といったケースでは、Unityの方が話が通りやすい場面が多いです。

## 5. コミュニティと会社としての性格

### Godot：コミュニティ主導＋非営利財団

Godotは、Godot Foundationという非営利団体と世界中のコントリビュータによって開発 されています。

- 開発はGitHub上で完全に公開
- 機能追加や仕様変更もオープンなプロセス
- 「エンジンの方向性が、株主や売上ではなくコミュニティの利便性寄りになりやすい」

という性格があり、
「急に料金体系が変わってビジネスモデルが崩れるリスクが非常に低い」 のがメリットです。

### Unity：巨大企業の製品としての安定とリスク

Unityは、Unity Technologies社の商用製品 です。
ゲームだけでなく、映像・自動車・建築など様々な産業向けにも展開しています。

一方でここ数年は、

- Runtime Fee騒動に伴う信頼低下
- 2024〜2025年にかけての大規模レイオフ（人員削減）

など、ビジネス面での不安定さが話題になることも多い 状況です。

エンジン自体は成熟しておりユーザーも多いものの、

- 「今後また料金や利用条件が変わる可能性はゼロではない」
- 「長期運用するSaaSやライブサービスゲームなどは、契約条件も含めて常にチェックが必要」

という前提で付き合う必要があります。

## 6. どっちを選べばいい？ざっくり指針

### Godotを選びやすいケース

- 個人・小規模チームの2Dゲーム（ローグライト、メトロイドヴァニア、ADVなど）
- エンジンのライセンスコストをゼロにしておきたい
  （教育、研究、趣味開発、収益予測が立たないインディーなど）
- プログラミング初心者で「ゲームからコードを学びたい」
- オープンソースや自前改造を重視したい（ツールを作り込む、社内専用ビルドを作る等）

### Unityを選びやすいケース

- 最初から モバイル＋コンソール＋PC のマルチプラットフォーム展開を狙う
- VR/AR、3Dアクション、オンライン要素のあるゲームなど、Unityの事例が豊富なジャンル
- 既にチーム内にC#経験者が多い、あるいはエンジニア採用を前提としている
- 受託開発・企業案件で「Unity指定」「Unity実績」が強い武器になる

### 迷ったときのシンプルな決め方

- 「初めてゲームを作る・小さく始めたい」 → Godotから始めるのはかなりアリ
- 「コンソール前提／クライアントワーク前提／3Dガッツリ」 → Unityを候補の筆頭に

という感じで、「どちらか一方が上位互換」というわけではなく、用途と戦略で決める のが現実的です。

## まとめ

- Godotは 完全無料・MITライセンス・オープンソース で、2Dやインディー向けに扱いやすいエンジン
- Unityは 無料枠はあるが、一定規模からは有料サブスク必須。その代わり、コンソールや3D・VR/ARなど商用タイトルの実績とエコシステムが圧倒的
- ビジネス的な安定性重視ならGodot、業界標準スキルやコンソール展開重視ならUnity という棲み分けになりやすい

最終的には、

- 作りたいゲームのジャンル
- 出したいプラットフォーム
- チームのスキルセット
- 将来のビジネスモデル（趣味か、商用か）

を並べてみて、「今の自分たちにとってリスクが少なくて動きやすい選択肢はどっちか」 で決めるのが良いと思います。
